# Подготовка к публикации в Git

06.10.2026 владелец выбрал публичный репозиторий [Mgkgr/vpn_synology](https://github.com/Mgkgr/vpn_synology) и разрешил публикацию и развёртывание на NAS. Он настроен как `origin` текущего checkout `D:\Projects\vpn-gateway-dashboard`; рабочая ветка — `main`. Начальный коммит GitHub с README сохраняется в истории, force-push не требуется. Состояние подготовки на 04.10 ниже описывает проверки, выполненные до разрешения на публикацию.

## Что сохраняем

- Код панели/исполнителя, тесты, утверждённые планы и безопасные шаблоны.
- Не сохраняем `.env`, клиентские профили и ключи, рабочие конфиги Mihomo, SQLite вместе с WAL/SHM/journal, архивы, локальное окружение Python, браузерные traces и GeoData binaries.
- Служебные имена хостов, IP и эксплуатационные заметки не всегда являются секретами, но тоже требуют просмотра перед открытой публикацией. Проверка ключей не является проверкой приватности всей документации.

Внешнее backup-хранилище исключено из текущего объёма по решению владельца. Локальное зашифрованное резервирование NAS остаётся: один Git не восстановит идентичность WireGuard-сервера и базу клиентов. Утрата NAS вместе с локальной копией не покрывается этой схемой. Пароль восстановления и перенос клиентских ключей в Git не допускаются, даже если репозиторий закрытый.

## Проверка без публикации

Используется официальный [Gitleaks](https://github.com/gitleaks/gitleaks/tree/v8.30.1), проверен CLI 8.30.1. Бинарный файл установите отдельно из официального релиза с проверкой checksum; скрипт ничего не скачивает и не устанавливает автоматически.

Из корня проекта:

```powershell
python deploy/check-git-publication.py --gitleaks "C:\Tools\gitleaks.exe"
if ($LASTEXITCODE -ne 0) { throw 'Publication check failed' }
```

Альтернатива — `GITLEAKS_PATH` или `gitleaks` в PATH. Команда проверяет:

1. Нет ли в индексе runtime-файлов, которые уже должны быть исключены.
2. Историю всех локальных refs, включая старые версии удалённых файлов.
3. Staged diff: секрет не должен исчезнуть из проверки после удаления только из рабочей копии.
4. Текущие tracked и неигнорируемые untracked файлы во временном каталоге, который удаляется после проверки. Внешние пути, symlinks и submodules не экспортируются молча.

Флаг `--redact=100` обязателен; вывод скрипта содержит только этапы и координаты находок, без `Secret`/`Match`. Команда не выполняет `git add/commit/push`, не устанавливает hooks, не меняет постоянную Git-конфигурацию и не обращается к NAS. Сетевой доступ для сканирования не нужен. Это ручная проверка: автоматический pre-commit/CI пока не установлен.

`.gitleaks.toml` дополняет штатные правила детектора форматами VLESS, HY2/Hysteria2/Trojan и WireGuard private/preshared key. Разрешены только проверенные тестовые значения **в конкретных тестовых файлах**. Нет общего исключения `tests/`, baseline всех находок или отключения стандартного поиска API-ключей. Тесты проверяют, что другой ключ в том же файле и заглушка в другом файле блокируются.

## Если проверка остановилась

- Не добавляйте весь каталог в исключения и не публикуйте обходным путём.
- Реальное ранее закоммиченное значение требует отдельного решения об отзыве/ротации и очистке истории; удаление только последней версии недостаточно.
- Для подтверждённой заглушки допустимо узкое исключение по точному значению и пути с регрессионным тестом.
- Runtime-файл, уже попавший в индекс, требует осознанного удаления из индекса, а не удаления рабочей базы/конфига. Скрипт сам этого не делает.

После успешного сканирования просмотрите diff и добавьте только выбранные файлы по явным путям. Повторите проверку перед push. Успех сканера не доказывает отсутствия любого возможного секрета и не разрешает автоматическую публикацию. `deploy-hardened.ps1` разворачивает Git HEAD, поэтому незакоммиченные изменения интерфейса на NAS не попадут.

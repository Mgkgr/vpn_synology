## DNS-контракт

В pinned Mihomo 1.19.28 SOCKS-запрос сохраняет доменное имя. Поэтому одного
наличия разрешённого IP в основном Mihomo недостаточно для работы ByeDPI.
Использована штатная возможность
[импорта domain/classical rule-set в fake-ip-filter](https://wiki.metacubex.one/en/handbook/syntax/#introducing-domain-sets):
`rule-set:managed-antidpi`. Только этот набор получает реальные IP; прочие
домены сохраняют FakeIP. Режим blacklist, существующие wildcard-исключения,
upstream DNS, `respect-rules`, порядок маршрутов и fallback не переписываются.
Неподдержанный режим или несовпадение provider-контракта блокирует подготовку.

Конкретное применение пока выполнено **только к синтетическому Mihomo в стенде**.
На NAS прочитаны лишь разрешённые несекретные DNS-параметры рабочего шлюза.

Для domain-режима требуются read-only `/run/config/dns.json` и `/etc/resolv.conf`:
один числовой адрес DNS шлюза, без Docker/provider fallback и search domains,
`timeout:1 attempts:1`. Несовпадение файлов запрещает запуск. Auth-Mihomo тоже
использует только этот DNS и проверяет FakeIP после разрешения домена. Его DNS
служит внутренним resolver, не открывает отдельный listening port. Без явного
контракта остаётся прежний IP-only режим `--no-domain`.

Это не полноценная защита от произвольной подмены DNS во время работы:
auth-Mihomo и ByeDPI выполняют два разрешения, поэтому перед production нужны
контроль целостности DNS-контракта, исключение DNS control-plane из antiDPI
маршрутов и проверка поведения при изменении ответа между запросами. Секрет
основного controller новому сервису не передаётся.

## Восстановление и границы

Подготовлен чистый planner `antidpi-lifecycle.py`: проверяет image ID, scope/run/
role labels, container ID и настоящий inode namespace; при несовпадении требует
пересоздать SOCKS, а не просто restart. Остановленный owner не вызывает запуск
слепого joiner. Есть 300-секундный cooldown; закрытие старого слушателя не
откладывается этим cooldown. Happy-path не требует операций.

На NAS этот planner исполнял **ручной ограниченный harness**, защищённый отдельной
блокировкой. Производственный boot/watch reconciler и интеграция с общей
maintenance-блокировкой ещё не установлены; reboot самого NAS не выполнялся.
Task 7 целиком не завершён. Default Compose всё ещё IP-only и без внешней сети.

До production: проверенный encrypted backup/restore, DNS drift/control-plane
guard, прикладные TCP/TLS/DPI тесты на согласованных сайтах, ресурсные/длительные
тесты, затем отдельная регистрация маршрута и worker. UDP/QUIC и IPv6 этим
runtime не обслуживаются; нельзя незаметно переводить их в DIRECT.

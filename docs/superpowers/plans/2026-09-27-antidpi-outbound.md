# Отдельный anti-DPI-выход — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:executing-plans`. Выполнять задачи с отметками `- [ ]` самостоятельно в текущей сессии, без агентов — выбор пользователя. Спецификация утверждена; этот актуализированный план ожидает проверки. Не устанавливать одновременно оба движка «на всякий случай».

**Goal:** добавить отдельно назначаемый маршрут `ANTIDPI` и управление его стратегиями для существующих WireGuard-клиентов, не меняя их профили и два работающих VPN.

**Architecture:** официальный Zapret2 + HevSocks5Server в отдельном сетевом namespace при подтверждённой поддержке NFQUEUE; иначе ByeDPI с закрытым авторизованным SOCKS-входом. Mihomo направляет сюда только явно назначенные правила. Панель и Telegram используют общий реестр и состояния предыдущего этапа.

**Tech Stack:** Docker Compose Synology, nfqws2/HevSocks5Server либо ByeDPI/Mihomo, существующие Python/FastAPI и React. Версии/commit/digest фиксируются до сборки; установщик Z2K и старый tpws не используются.

**Spec:** `docs/superpowers/specs/2026-09-27-antidpi-telegram-design.md`.

## Global Constraints

- Обязательный предыдущий этап: `docs/superpowers/plans/2026-09-27-outbound-health-telegram.md`, задачи 1–5; развёртывание Telegram не блокирует локальную разработку этого этапа.
- Для задачи 5 нужны worker, owner step-up и BackupManager из задач 1–4 `2026-09-27-component-maintenance.md`, для задачи 6 — общий job UI из задачи 5 того плана. Эти компоненты не являются зависимостью read-only preflight/изолированного runtime.
- Новый ID `ANTIDPI`, название показывает фактический движок `Zapret2` или `ByeDPI`. Это не VPN с зарубежным IP.
- `VPS-FALLBACK` остаётся `WG-IMP → HY2-USA`; никакого автоматического переключения ANTIDPI в DIRECT/VPN.
- Отдельный namespace, без host network, Docker socket, privileged и опубликованных SOCKS-портов. Секреты `0600`, вне Git.
- Не загружать модули ядра и не менять firewall DSM автоматически. Недоступный NAS/неполные сведения — `unknown`, не доказательство несовместимости NFQUEUE.
- NFQUEUE без `queue-bypass`; при отказе обработчика новый и существующий тестовый трафик не должен тихо уйти без обработки.
- DIRECT имеет прежний приоритет. Тестовые домены согласуются отдельно; массовые назначения, замена DNS NAS и отмена ограничений UDP/443 не входят в установку.
- Текущие клиентские ключи, базы, проекты, OpenVPN и роутеры не изменяются. Новые скрипты — UTF-8, `.sh` LF; Python-helper NAS совместим с 3.8.
- Для автоподбора наблюдаются оба направления только соединений SOCKS в новом namespace. Использовать штатные `circular`/детекторы Zapret2, не второй независимый алгоритм ротации.
- До 1000 автоматических записей, срок неактивности 30 дней; до 128 закреплений, без автоматического удаления. Ручной подбор: одно задание/один публичный домен, максимум 60 попыток/20 минут, отдельное применение результата.
- Нет произвольного Lua, shell, путей или загрузки стратегий по URL из панели. WARP, внешняя телеметрия Z2K и смена маршрутов по результатам подбора не добавляются.

## Review Focus

1. «Модуль не загружен»/нет `/proc/config.gz` ошибочно принимают за отсутствие NFQUEUE: решение только по доказательствам; задача 1.
2. После рестарта соседний контейнер остался в старом namespace: старый SOCKS не принимает рабочий трафик, восстановление нового сервиса проверяется явно; задачи 2, 7.
3. Умер nfqws2, а существующее TCP-соединение продолжает DIRECT: проверяются не только healthcheck и новые соединения; задачи 2, 7.
4. Неавторизованный SOCKS, FakeIP, IPv6/DNS-петля или DNS rebinding тестового домена: не обходить auth/SSRF и не объявлять UDP/QUIC готовыми по наличию флага; задачи 2, 3, 5, 7.
5. Параллельная правка, устаревшее закрепление или снятый входящий перехват: не терять настройки и не показывать рабочий автоподбор без данных; задачи 3, 5–7.

## Критерий завершения

Недостаточно запущенного контейнера. Нужны проверенный целевой сервис, отсутствие обхода при отказе, сохранность двух VPN/DIRECT/клиентских ключей, правильное состояние в панели, проверка restart/rollback, auto/pin/подбора и честный отчёт об UDP/QUIC. Если gate не пройден, соответствующая стадия остаётся невыполненной.

Основа адаптера: [официальные circular и детекторы Zapret2](https://github.com/bol-van/zapret2/blob/master/lua/zapret-auto.lua). Это переиспользование штатного механизма с нашим ограниченным управлением и хранением, не перенос установщика Keenetic или второго алгоритма переключения.

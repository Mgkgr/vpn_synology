# VPN Dashboard — проектное решение

## Принятое направление

Кабинет доступен только из `192.168.2.0/24` и через WireGuard; в WAN он не публикуется. Визуально он использует тёмную, сдержанную операционную стилистику: тонкие разделители, таблицы вместо вложенных карточек, синий только для действия и маршрута, зелёный/янтарный/красный только для состояния.

Первый экран строится по мотивам первого утверждённого варианта, второй — по мотивам карты маршрута из третьего. Это две отдельные страницы, а не объединённая перегруженная сводка.

## Навигация и сценарии

### Обзор

Первый рабочий экран отвечает на вопрос «всё ли работает сейчас?»:

- состояние WireGuard, Mihomo, MetaCubeXD и Uptime Kuma;
- текущий активный выход `WG-IMP` со статусом «Основной»;
- отдельная строка `HY2-NL` со статусом «Резервный, ожидает»;
- активные клиенты WireGuard, их последний handshake и текущий трафик;
- переключатель периода «Месяц / Год» и суммарный входящий/исходящий трафик;
- последние события: health-check, смена выхода, handshake, обновление GeoIP/GeoSite;
- дата и результат последнего обновления геоданных.

Панель не показывает `WG-IMP → HY2-NL` как последовательный маршрут. Это два альтернативных выхода fallback-группы.

### Маршруты

Второй экран отвечает на вопрос «куда сейчас идёт трафик и почему?»:

- карта `WireGuard clients → Mihomo` с двумя расходящимися ветками;
- сплошная синяя ветка к `WG-IMP` — активный основной выход;
- пунктирная ветка к `HY2-NL` — резерв, который используется только после провала проверок основного;
- справа — инспектор выбранного выхода: последние тесты, RTT, HTTP-результат, время последней смены и причина переключения;
- таблица текущих соединений Mihomo с клиентом, назначением, объёмом и временем жизни;
- снизу — трафик за месяц или год и история смен выходов.

### Клиенты

Отдельная страница профилей WireGuard: создание профиля, имя, QR-код, скачивание `.conf`, отзыв, статус, последний handshake, месячный и годовой трафик. Внешне это таблица с карточкой создания, а не встроенный iframe wg-easy. wg-easy остаётся как отдельная аварийная расширенная панель.

### Правила

Показывает применённую цепочку Mihomo, `direct.txt`, активные `GEOIP`/`GEOSITE`-правила, private-исключения и fallback. В первом релизе поиск выполняется по реально загруженным правилам и rule-provider'ам: тип, payload, число записей, источник, последняя активность и дата обновления. Полный перебор содержимого бинарных GeoIP/GeoSite-баз намеренно не добавляется: это отдельная тяжёлая функция, не нужная для управления текущим шлюзом. Изменение своего DIRECT-списка проходит валидацию, показывает diff, создаёт ревизию и только затем перезагружает конфигурацию Mihomo.

### Обновления и журнал

Обновления отображают версии/контрольные суммы/дату GeoIP и GeoSite, следующий автозапуск и историю попыток. Ручное обновление использует документированный контроллер Mihomo `POST /upgrade/geo`; перед операцией dashboard сохраняет собственный снимок метаданных и после неё проверяет новую версию и дату файлов. При ошибке запись фиксируется, а действующие данные Mihomo не подменяются dashboard. Журнал хранит проверки URL, задержку, HTTP-результат, использованный выход, смены fallback и административные действия.

## Архитектурный выбор

Выбран отдельный контейнер `vpn-dashboard` с React-интерфейсом и небольшим API-сервисом. Это предпочтительнее двух альтернатив:

1. Прямой доступ браузера к API Mihomo и wg-easy — отклонён: раскроет секреты контроллера и не даст безопасно вести историю.
2. Встраивание Grafana/Uptime Kuma/wg-easy в iframe — отклонено: получится несколько несогласованных интерфейсов, а создание конфигов и правила останутся вне единого сценария.
3. Отдельный dashboard-адаптер — выбран: он выдаёт только необходимые данные, хранит историю в собственной SQLite-базе и не получает Docker socket.

Сервис подключается к локальным API Mihomo и wg-easy по внутренней сети, использует отдельные секреты только внутри контейнера и предоставляет интерфейс на LAN-адресе NAS. wg-easy фиксируется на `v15.2.2`; его API помечен upstream как нестабильный, поэтому адаптер проходит контрактную проверку при старте и блокирует операции с профилями при несовпадении ответа. Состояние контейнеров определяется HTTP-проверками их локальных endpoint'ов, а не доступом к Docker socket.

## Сбор данных и хранение

- раз в минуту: активность WireGuard, последний handshake, счётчики peers, доступность сервисов;
- раз в пять минут: тест каждого выхода через контроллер Mihomo на настроенных URL;
- сразу при обнаружении: запись смены активного fallback-выхода;
- раз в сутки: проверка GeoIP/GeoSite и статуса автообновления;
- SQLite хранит сырые проверки 90 дней, часовые сводки 12 месяцев и месячные сводки бессрочно до ручной очистки;
- текущие суммарные счётчики WireGuard используются как точка старта: достоверная разбивка по месяцам появляется с момента запуска dashboard.

## Безопасность и отказоустойчивость

- порт dashboard привязан только к `192.168.2.103`; доступ через WAN отсутствует;
- самостоятельная учётная запись dashboard, хэш пароля и интеграционные секреты — в файлах `0600`;
- API не возвращает ключи, приватные конфиги или секреты в журналы;
- операции создания/отзыва профиля и обновления данных фиксируются в журнале;
- конфигурация и база dashboard входят в зашифрованный локальный backup перед изменениями;
- контейнер имеет `restart: unless-stopped` и healthcheck; отдельный autoheal не добавляется в первом релизе.

## Проверка результата

1. В LAN видны только dashboard, MetaCubeXD, Kuma и wg-easy; с WAN они недоступны.
2. Созданный в dashboard профиль скачивается и показывает QR; новый peer появляется в списке и его handshake виден после подключения.
3. При отключении `WG-IMP` маршрут меняется на `HY2-NL`; запись содержит причину, время и результаты тестов.
4. DIRECT-домен виден в правилах и не использует fallback.
5. Ручное обновление GeoIP/GeoSite фиксирует дату, версию и резервную копию; при ошибке старая версия остаётся активной.
6. Значения «месяц» и «год» совпадают с накопленными snapshot-дельтами peers.

## Принятые допущения

- В первом релизе два выхода: основной `WG-IMP`, резервный `HY2-NL`; Reality/XHTTP добавляются позже без перестройки интерфейса.
- Используются минимум три внешние проверки: Cloudflare `generate_204`, GitHub API и Google `generate_204`; набор редактируется в dashboard.
- У dashboard один владелец-администратор.
- Пользователь выбрал первый и третий визуальные варианты как основу двух отдельных страниц и дал указание приступить к работе.

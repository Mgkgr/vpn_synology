# Суточные проверки сервисов на плитках правил

04.10.2026. Пользователь одобрил: один контрольный сайт сервиса, ежедневно в 04:30, отдельно DIRECT / основной / резервный; дата, миллисекунды и ошибка; без влияния на fallback. Общей GeoIP/широкой категории нельзя приписывать проверку всех входящих сайтов. Работа в текущем checkout, без агентов. Документ уточняет техническую реализацию; установка на NAS отдельно от локального кода.

## Смысл результата

- Это контрольный HTTPS HEAD к конкретному URL, не ICMP ping, speedtest или доказательство работы приложения/авторизации/видео/UDP.
- На плитке — компактное состояние трёх путей, время замера и пометка «контрольный сайт». Подробности URL/ошибки раскрываются рядом с выбором маршрута.
- Задержка — время ответа HEAD, не пропускная способность. HTTP 2xx/3xx считать ответом допустимого класса, без перехода по редиректу; 4xx/5xx — ответ вне ожидаемого класса, а не «VPN умер».
- Если контроллер не отдаёт точный HTTP-код либо первопричину TLS/DNS, не выдумывать их: показывать измеренный класс/таймаут либо «причина не уточняется API». Сайт, доступный по HEAD, всё равно может требовать CAPTCHA/входа в приложении.
- Категории без сопоставленного контрольного URL: «Для категории нет единого контрольного сайта». Старше 25 часов — «данные устарели», до первого прогона — «ещё не проверено»; устаревшее зелёное состояние не выдавать за текущее.

## Изоляция

Три новые скрытые singleton-select группы: `DASH-SITE-DIRECT`, `DASH-SITE-WG-IMP`, `DASH-SITE-HY2-USA`; единственный участник соответственно `DIRECT`, `WG-IMP`, `HY2-USA`. `interval: 0`, `empty-fallback: REJECT`. Они не входят в рабочий fallback, правила клиентов или health-коллектор. Не переиспользовать `DASH-HEALTH-*`: их история нужна оповещениям.

Новый метод клиента принимает только ключ из фиксированного каталога и один из трёх route IDs. Запрещены произвольный URL/имя прокси, PATCH/PUT групп, вызов `/delay` на `WG-IMP`, `HY2-USA`, `VPS-FALLBACK` или `DASH-HEALTH-*`. Перед пачкой проверить структуру групп, после ошибки — доступность контроллера. Отсутствие/неправильная группа — `unknown`, без попытки «починить» живую конфигурацию.

Обоснование по pinned Mihomo v1.19.28: [URLTest](https://github.com/MetaCubeX/mihomo/blob/v1.19.28/adapter/adapter.go) записывает history/alive своего wrapper; [Selector](https://github.com/MetaCubeX/mihomo/blob/v1.19.28/adapter/outboundgroup/selector.go) передаёт DialContext единственному участнику без его URLTest. [Controller](https://github.com/MetaCubeX/mihomo/blob/v1.19.28/hub/route/proxies.go) отдаёт задержку, но не полноценный HTTP-отчёт. Это основание дизайна, не замена изолированной live-проверки установленного бинарного файла.

## Каталог и ограничения запросов

Отдельный модуль с контрольными HTTPS URL. Пользовательский DIRECT-список не превращается в список сетевого сканирования. Каталог не меняет правила/выбор маршрута.

В первый каталог включить точные сервисы текущих плиток: OpenAI/ChatGPT, Anthropic, Google, GitHub, YouTube, Telegram, Microsoft, Apple, Netflix, Spotify, X, TikTok, Disney+, HBO, Prime Video, Twitch, DAZN, Bilibili, Bilibili International, Steam, EHentai, Speedtest, Кинопоиск, Ozon, Wildberries, Авито, Сбер, Т-Банк, Яндекс, VK, Mail.ru, СДЭК, МегаФон, МТС, Ростелеком, Т2. Один HTTPS URL на сервис проверяется по официальному источнику; Speedtest получает только HEAD, не загрузку файлов. Для Yandex/Google и подобных явно писать, что это не проверка всех их продуктов. Широкие категории и GEOIP без измерений.

Разрешить только фиксированные публичные HTTPS имена, порт 443, без credentials/query/fragment. Не следовать редиректам. DNS preflight через Mihomo отклоняет пустые, частные, loopback/link-local и FakeIP ответы; ошибка проверки DNS — `unknown`, запрос к сайту не отправляется. Это предварительная проверка, не криптографическая гарантия неизменности DNS между двумя обращениями; произвольные пользовательские хосты остаются запрещены.

## Расписание, данные и нагрузка

- Часовой пояс `Asia/Yekaterinburg`, 04:30. Не зависеть от UTC контейнера или часового пояса браузера.
- Не более одного сетевого теста одновременно, один HEAD на маршрут/сервис, таймаут Mihomo 10 секунд, timeout controller 12 секунд, вся пачка не более 25 минут. Открытие страницы не запускает тесты.
- Персистентный уникальный run на локальную дату в SQLite: `running`, `completed`, `interrupted`. Захват даты атомарный; второй процесс/рестарт не повторяет уже начатую пачку в ту же дату. После аварии показать неполный прогон, следующий — на следующую дату. Один catch-up для текущей даты после 04:30, без многодневного догоняния; до 04:30 не запускать.
- Сохранять каждый результат отдельно: service key, route ID, подпись выхода на момент проверки, URL, `observed_at`, state (`responded`, `http_rejected`, `failed`, `unknown`), delay nullable, безопасный reason code. Не сохранять payload/headers/tokens или посещения пользователей.
- История 30 дней. `/api/rules/service-checks` читает только SQLite и каталог, доступ только администраторам; при ошибке чтения остальная страница правил работает.
- Флаг включения по умолчанию выключен до provisioning/приёмки. Не выдавать выключенный сбор за незаметно работающий. Состояние настройки и время следующего прогона видны в API/UI.

## Развёртывание и приёмка

Локальный релиз включает код, тесты, UI и чистый config-transform с проверкой известных anchors. Он не делает SSH-запись, hot-reload или перезапуск сам. Применение требует свежей локальной зашифрованной копии, CAS исходной конфигурации, Mihomo `-t`, изолированной проверки wrapper-history и отдельного безопасного окна reload. После этого включить планировщик и проверить первый прогон. Нельзя проверять изоляцию отключением рабочего VPN.

На NAS сравнить до/после проб: члены/выбор/health history рабочего fallback не изменены тестами; новые группы не доступны как клиентские назначения; DNS и маршруты DSM не менялись. Если это не доказано, сбор остаётся выключенным. Внешний backup и сторонний монитор не входят в эту задачу.

# Доработка наблюдаемости VPN Dashboard

## Цель

Сделать панели «Обновления», «Правила», «Клиенты», «Маршруты» и «Журнал» пригодными для ежедневного управления шлюзом: с достоверным временем событий, понятными состояниями загрузки и без задержанной реакции интерфейса.

## Границы

Входят: dashboard backend/frontend, его SQLite и уже существующие Mihomo/wg-easy API.

Не входят: новые контейнеры, изменение VPN-маршрутизации, открытие новых портов, внешние системы мониторинга и передача секретов в UI.

## Обновления GeoData и правил

`GET /api/updates` возвращает:

- состояние GeoSite, GeoIP, country MMDB и ASN: имя файла, размер, SHA-256, время модификации и время последнего успешного снимка;
- объединённую отметку времени, если файлы были обновлены одним запуском;
- историю ручных/автоматических обновлений GeoData;
- ревизии `direct.txt` и управляемых GeoSite/GeoIP-политик с автором и временем.

Время файла — наблюдаемое состояние на NAS; время записи обновления — время подтверждённой проверки dashboard. Если записи ещё нет, интерфейс так и пишет, не подменяя неизвестное время текущим.

## Каталог правил

Каталог ограничен наборами, существующими в используемой поставке MetaCubeX. В первом релизе отображаются AI, Google, GitHub, YouTube, Telegram, Microsoft, Apple, Netflix, Spotify, социальные сети, а также GeoIP для Google, Telegram, Cloudflare, Netflix, CloudFront и стран.

AI представлен как отдельные OpenAI и общий `category-ai-!cn` набор. Подписи поясняют охват: общий AI-набор предпочтителен для единого маршрута OpenAI/Claude/Gemini и связанных доменов; узкий OpenAI остаётся для избирательного правила.

Страница правил показывает skeleton/индикатор до завершения загрузки каталога, активных политик и текущих правил Mihomo. Ошибка загрузки остаётся отдельным состоянием и не маскируется пустой таблицей.

## Клиенты

Удаление и отключение подтверждаются собственным modal-диалогом dashboard, а не `window.confirm`. Успешная операция вызывает toast; удалённый клиент немедленно удаляется из кеша React Query, после чего список и счётчики сверяются с wg-easy. При ошибке клиент возвращается, а toast показывает безопасную причину.

## Проверки маршрутов

Пользователь может добавить, переименовать, включить или отключить проверку. Для каждого адреса backend разрешает только `https`, порт 443 по умолчанию или явный 443, публичный DNS-результат вне loopback/link-local/private/reserved диапазонов и отсутствие учётных данных в URL. Перед сохранением URL нормализуется; повторяющиеся адреса запрещены.

`POST /api/probes/run` запускает один цикл проверки сразу. Одновременно допускается только один ручной или плановый цикл; повторный запрос получает конфликт, а интерфейс показывает «Проверка уже выполняется». Результаты пишутся в журнал. Пользователь видит две последние проверки на странице; полный список открывается через disclosure.

Ошибки проверки содержат безопасное диагностическое поле: HTTP-статус или краткую причину Mihomo, без URL с секретами и без внутренних адресов. Это позволяет отличить неверный endpoint от недоступного выхода.

## Журнал

Успешные и неуспешные входы, создание/переименование/включение/отключение/удаление клиента, изменение списков проверок, прямых правил и GeoSite/GeoIP-политик пишутся с временем, исполнителем, действием, объектом и результатом. Журнал отображает это в понятных русских подписях и сохраняет возможность фильтрации.

## Тестирование и проверка

- backend: тесты API для metadata GeoData, ревизий правил, аудита входа, безопасных пользовательских целей, запуска проверки и блокировки параллельного запуска;
- frontend: тесты optimistic удаления, toast/modal, loading-state правил, двух последних проверок и раскрытия полной истории;
- интеграционно: проверить реальную ошибку Mihomo delay API до и после добавления безопасной причины, не менять конфигурацию выходов без отдельного решения;
- UI: открыть внешнюю панель, проверить отсутствие системных диалогов, немедленное изменение списка и доступность кнопки «Проверить сейчас».

## Безопасность

Пользовательские проверки не становятся SSRF-механизмом: URL валидируются до записи и повторно перед запросом Mihomo, внутренние сети и произвольные порты исключены. Секреты контроллера, wg-easy и VPN-профилей не входят в ответы API, журнал и сообщения ошибок.

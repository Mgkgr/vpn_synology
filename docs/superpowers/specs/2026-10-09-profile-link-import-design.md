# Самостоятельная замена VLESS/Hysteria2 по ссылке

Поручение 09.10: форма для типовых ссылок и запуск присланного VLESS. Пользователь
ранее поручил выполнять без повторных согласований, в текущем checkout и без
агентов. Присланный ключ не включается в документы/исходники/журнал/Git.

## Интерфейс и область

«Маршруты → Ключи VPN»: вставка одной `vless://`, `hy2://` или `hysteria2://`
ссылки, предварительный просмотр протокола, публичного сервера, порта и цели.
VLESS TCP/REALITY/Vision заменяет только основной `WG-IMP`, Hysteria2/salamander —
только резервный `HY2-USA`. Исторические ID, fallback, правила, DNS, WireGuard и
остальные контейнеры сохраняются. Регион из подписи ссылки не считается
доказательством страны выхода. XHTTP/подписки/произвольный JSON не поддерживаются.

Порядок: разобрать → проверить отдельно → применить. URI очищается из поля после
успешного разбора, не сохраняется в URL/localStorage/sessionStorage. Показываются
реальный этап задания, результаты по контрольным сайтам, даты и ошибка без
секретов. Открытие страницы не запускает пробы. При потере ответа отслеживается
старый job ID, повторное применение не отправляется.

## Защищённая граница

Ссылка поступает HTTPS POST под сессией владельца+CSRF, затем через существующий
локальный IPC. Worker сам строго разбирает её; неизвестные/дублированные параметры,
управляющие символы, не-TLS, некорректные ключи, private/FakeIP адреса отвергаются.
Для VLESS принимается также `spx` как совместимая метка импорта, но Mihomo не
получает неподдерживаемое поле. Ни shell, ни путь, ни Docker image не приходят
из браузера. Сетевой endpoint проверяется как публичный до испытаний.
Изолированная проверка и последующее применение используют один проверенный
публичный IP сервера с исходным TLS SNI. Этот IP показывается в форме; при смене
IP у провайдера требуется повторный импорт/проверка ссылки. Это исключает смену
адреса через DNS между проверкой и применением.

Разобранный секретный черновик хранится только в root-owned каталоге worker0700,
файл0600, 30 минут, максимум восемь черновиков; в задании только случайный ID и
ревизия. API/журнал/общие SQLite intents никогда не содержат URI, UUID, паролей,
obfs-secret, public-key/short-id или полного конфигурационного файла. Предпросмотр
возвращает только безопасную метаинформацию. Владелец подтверждает проверку и
применение существующим одноразовым operation-bound grant; пароль worker не видит.

## Проверка и применение

Один durable job под общей maintenance-блокировкой. Изолированный тестовый
Mihomo из установленного закреплённого образа: отдельный namespace, без TUN/DNS,
без публикации портов, без NET_ADMIN, non-root, readonly, временная аутентификация
proxy. Только новый профиль и MATCH на него; DIRECT-обход отсутствует. Endpoint
проверки фиксирован: Cloudflare204, Google204, GitHub200, 3 раунда, необходимо
минимум 2/3 у каждого. Тайм-ауты/объём ответа ограничены, TLS проверяется,
редиректы запрещены; временный контейнер удаляется по точному собственному имени.

Применение допускается после успешной проверки того же черновика/ревизии не
старше пяти минут. Сначала зашифрованная резервная копия с реальным пробным
восстановлением, полная валидация конфигурации и повторная проверка ревизии;
затем acknowledged reload Mihomo без рестарта контейнеров и контроль через
существующую изолированную `DASH-HEALTH-*` группу, не `/delay` рабочего fallback
участника. Проверяются сохранение второго профиля/правил/групп и 2/2 успеха на
каждом контрольном сайте. Файл фиксируется только после проверки runtime.

При неудаче восстанавливается только собственное состояние; конкурентная новая
ревизия не перезаписывается. При неподтверждённом reload/rollback — явное
`needs_reconcile`, блокировка сохраняется. Незавершённое задание после рестарта
не повторяет применение вслепую. Секретный черновик удаляется после успешной
замены либо по TTL. Краткое изменение соединений при reload объясняется в форме.

## Приёмка

Строгий парсер и отсутствие секретов в ошибках/снимках/SQLite, anonymous/admin/CSRF/
owner-grant ограничения, успешный/неуспешный тест, CAS, rollback, lost-response,
повтор одного ID, отмена и restart recovery. Проверки UI desktop/mobile,
клавиатура/очистка поля/невыдуманный прогресс. На NAS отдельно проверяются новый
VLESS, установленная форма и настоящая IPC-интеграция; отсутствие сессии владельца
не компенсируется поддельным входом или grant.

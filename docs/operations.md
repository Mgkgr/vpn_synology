# Эксплуатация VPN Dashboard

## Backup и восстановление

`deploy/scripts/backup-dashboard.sh` создаёт консистентный SQLite snapshot, сохраняет закрытую конфигурацию dashboard и persistent-конфигурацию VPN-шлюза в зашифрованный Restic-репозиторий. Пароль Restic хранится отдельным файлом с правами `0600`; он не попадает в Git или Hyper Backup логи.

Synology Task Scheduler запускает backup ежедневно в 03:30 `Asia/Yekaterinburg`. Hyper Backup должен реплицировать каталог `/volume1/docker/vpn-gateway/backups/dashboard/restic`. Раз в месяц запускается `restore-verify.sh`; он выполняет `restic check`, восстановление в scratch-каталог и `PRAGMA integrity_check`.

Перед аварийным восстановлением остановите dashboard, восстановите последнюю snapshot-копию, верните `dashboard.env` с исходным `DASHBOARD_ENCRYPTION_KEY`, затем запускайте проект. Новый ключ шифрования без миграции сделает сохранённые credentials wg-easy недоступными.

## Безопасное развёртывание

Перед первым запуском hardened-версии root выполняет `deploy/scripts/prepare-runtime.sh`. Он проверяет обязательный ключ, требует localhost-bind, переводит только данные dashboard и его управляемые rule-файлы к непривилегированному UID `10001`, затем запускает `docker compose config --quiet`. Скрипт не перезапускает `vpn-wireguard`, Mihomo или wg-easy.

Dashboard не получает bind-mount каталога Mihomo целиком: ему доступны только `GeoIP.dat`, `GeoSite.dat` в режиме чтения и каталог `rules` для управляемых DIRECT-правил. Конфигурация Mihomo и outbound-секреты не монтируются в контейнер панели.

DSM Reverse Proxy должен направлять `https://roaring.crazedns.ru:10443` на `http://127.0.0.1:8088`. Прямой доступ к `8088` из LAN и WAN после этого отсутствует.

Для повторяемого обновления используется `deploy/deploy-hardened.ps1`. Он передаёт на NAS архив только из Git HEAD, поэтому не затирает `dashboard.env`, SQLite, rule revisions и backup. Скрипт потребует пароль sudo один раз для preflight, после чего вызывает уже ограниченный `vpn-dashboard-deploy` и status-check.

Образы в `Dockerfile` зафиксированы одновременно конкретным тегом и digest. Их не обновляет Watchtower: новый digest выбирают вручную после проверки upstream release notes, полного CI и пробной сборки.

## График трафика

Collector запрашивает первый безопасно ограниченный sample `/traffic` Mihomo ровно раз в минуту и записывает только скорость входящего и исходящего канала в SQLite. Обзор читает эти уже сохранённые точки — переключение 5 минут / 30 минут / 6 часов и периодическое обновление страницы не создают новых запросов к Mihomo. История minute-level хранится семь суток и затем удаляется ежедневной retention-задачей.

## Состояние NAS и контейнеров

Для карточки «Хост DS923+» DSM Task Scheduler запускает от `root` один лёгкий скрипт раз в минуту:

```sh
/bin/sh /volume1/docker/vpn-dashboard/deploy/scripts/collect-host-health.sh
```

Первый снимок можно безопасно создать из Windows командой `deploy/setup-host-health.ps1`: она попросит пароль `sudo`, выполнит только этот collector и выведет время созданного JSON-файла. Для постоянного обновления в DSM откройте **Панель управления → Планировщик задач → Создать → Запланированная задача → Пользовательский сценарий**. Укажите имя `VPN Dashboard — host health`, пользователя `root`, расписание «каждый день, повторять каждые 1 минуту» и приведённую выше команду. Сохраните задачу и нажмите «Запустить» один раз; первый CPU-снимок появится сразу, процент CPU — со второго запуска.

Скрипт читает только `/proc`, `df` и состояние пяти известных контейнеров через Docker CLI. Он записывает один атомарный JSON-снимок в `deploy/data/host-health.json`; контейнер панели читает его как непривилегированный UID `10001`, Docker-сокет в контейнер не монтируется. На первом запуске CPU отображается как «первая точка», потому что ещё нет предыдущего счётчика; начиная со второго виден процент использования CPU. Статус `absent`, рост числа перезапусков, ошибки/потери сети, нехватка памяти, swap и места на томе — признаки, которые нужно проверять до диагностики самого VPN.

## Локальные зашифрованные резервные копии

Restic хранит на самом DS923+ snapshot базы панели, владельцев и сессий, зашифрованные учётные данные wg-easy, файлы секретов панели, WireGuard-профили/ключи и persistent-данные Mihomo, wg-easy и Uptime Kuma. За счёт этого восстановление не требует перевыпускать конфигурации клиентам.

Файл пароля Restic должен быть отдельным, с правами `0600`, например `/volume1/docker/vpn-gateway/secrets/restic-password`. В DSM Task Scheduler нужны две задачи от `root`:

```sh
RESTIC_PASSWORD_FILE=/volume1/docker/vpn-gateway/secrets/restic-password BACKUP_TIER=frequent /volume1/docker/vpn-dashboard/deploy/scripts/backup-dashboard.sh
```

— раз в 5 минут, и та же команда с `BACKUP_TIER=daily` — раз в сутки в 03:30. Retention хранит 288 последних точек (24 часа при пятиминутном запуске), 14 дневных, 8 недельных и 12 месячных. Раз в месяц запускайте `restore-verify.sh` с тем же `RESTIC_PASSWORD_FILE` — он проверяет Restic, SQLite и наличие Dashboard/WireGuard persistence в restore-копии.

Это локальная защита от ошибки, не защита от утраты самого NAS. Внешняя репликация намеренно не включена в текущем релизе.

## Fallback и OpenAI

Цепочка выхода остаётся одной: `VPS-FALLBACK = WG-IMP → HY2-USA`. Панель не создаёт отдельный OpenAI-канал: при первом корректном старте она добавляет только отсутствующее правило `GEOSITE,openai → VPS-FALLBACK`. Уже созданное администратором правило для OpenAI не меняется. Это сохраняет выбранный режим «Авто VPN» и позволяет в «Правилах» при необходимости назначить OpenAI прямо на WG-IMP, HY2-USA или DIRECT.

`deploy/apply-fallback-policy.ps1` устанавливает approved health-check интервал `30` секунд, строго проверяет, что состав и порядок fallback не изменились, проверяет Mihomo-конфигурацию в контейнере и делает backup перед перезапуском только Mihomo. Скрипт **не** отключает WG-IMP или HY2-USA, поэтому не является имитацией аварии. Итог `FAILOVER_EXERCISE=not_run` — ожидаемый: фактическую проверку переключения проводят отдельным согласованным окном, когда короткое отключение выхода допустимо.

### Замена резервного Hysteria2-профиля

Для замены ключа и сервера резервного выхода используется:

```powershell
D:\Projects\vpn-gateway-dashboard\deploy\replace-hy2-profile.ps1
```

Скрипт запросит два секрета в маскированном вводе, поэтому они не попадут в историю PowerShell, исходный код, вывод или Git. Он передаёт на NAS временный файл с правами `0600`, сохраняет закрытый backup прежнего `hysteria2.env` и `config.yaml`, затем атомарно меняет `HY2-NL` на `HY2-USA` в Hysteria2-блоке, fallback-ссылке и provider правил. Политики из панели, GeoData, список правил и `WG-IMP` не пересоздаются и не отключаются.

Новый профиль проходит три проверки: синтаксис полной текущей конфигурации Mihomo, hot-reload через аутентифицированный controller и отдельный `proxy_delay` непосредственно через `HY2-USA`. `ports` включает port-hopping в формате Mihomo; при ошибке любой проверки применяются прежние secret/config и выполняется reload предыдущей версии. Перезагрузка controller может кратко оборвать SSH, и это не считается ошибкой: launcher ожидает опубликованный итоговый статус. Успешный вывод содержит `HY2_DELAY_MS`, `HY2_PORT_HOPPING=enabled` и путь к закрытому backup, но не содержит ключей.

## Российские маркетплейсы и доставка

Точные GeoSite-категории `ozon`, `wildberries`, `avito` и `yandex` назначаются в панели на `DIRECT`. Они лучше ручных корневых доменов для соответствующих сервисов, потому что обновляются вместе с GeoSite. `yandex` намеренно широк: Еда, Лавка и Go используют общие домены авторизации и инфраструктуры Яндекса.

Для Самоката и распространённых сервисов доставки используется отдельный проверенный импорт:

```powershell
D:\Projects\vpn-gateway-dashboard\deploy\apply-russian-commerce-delivery-direct.ps1
```

Импортёр нормализует только `DOMAIN-SUFFIX,...,DIRECT`, игнорирует уже существующие строки, создаёт зашифрованный backup и применяет один reload через `RuleService`. При неуспешном reload предыдущий `direct.txt` восстанавливается. Не добавляйте к этому набору IP-адреса CDN: сначала захватите трафик конкретного телефона.

```powershell
D:\Projects\vpn-gateway-dashboard\deploy\diagnose-russian-services-routing.ps1 -WatchSeconds 60
```

Пустой `-SourceAddress` означает наблюдение всех текущих клиентов. Для точного клиента передайте его VPN-адрес, например `-SourceAddress 10.66.0.5`. Диагностика read-only и выводит только адрес источника, домен или IP назначения, тип транспорта, применённое правило и цепочку — без ключей, конфигураций и секретов.

Чтобы правила из панели применялись, один раз запускается `deploy/configure-managed-rules.ps1` после развёртывания. Скрипт допускает только известную текущую структуру `direct-custom`, создаёт четыре file-provider (`managed-direct`, `managed-fallback`, `managed-wg-imp`, `managed-hy2-usa`), сохраняет зашифрованный backup и валидирует конфигурацию в Mihomo. При неизвестной или частично изменённой структуре он завершится без догадок и без изменения маршрутизации. После успешного запуска он перезапускает Mihomo и dashboard: на новом запуске dashboard создаст отсутствующее правило OpenAI → VPS-FALLBACK.

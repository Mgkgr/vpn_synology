# Замена выходного VPN по ссылке

Страница: **Маршруты → Ключи VPN**, `/routes/profiles`. Доступ к просмотру есть
у администраторов, к изменениям — только у владельца панели.

1. Вставить одну ссылку `vless://…`, `hy2://…` или `hysteria2://…` и нажать
   **Разобрать ссылку**. Поле очищается после разбора; рабочая конфигурация не меняется.
2. Проверить сервер и назначение: VLESS TCP/REALITY/Vision — основной выход,
   Hysteria2/salamander — резервный. Внутренние идентификаторы `WG-IMP` и `HY2-USA`
   сохраняются для совместимости правил; это не страна и не текущий протокол.
3. **Проверить ключ**, подтвердить паролем владельца. Изолированный контейнер
   проверяет Cloudflare, Google и GitHub (`robots.txt`, без API-квоты) по HTTPS,
   по три раза. Для каждого сайта
   нужны минимум две успешные попытки. Клиенты не переключаются.
4. В течение пяти минут нажать **Применить ключ** и отдельно подтвердить.
   Исполнитель создаёт зашифрованную резервную копию с проверкой восстановления,
   проверяет конфигурацию, перечитывает её в Mihomo и выполняет шесть HTTPS-проб.
   Возможны краткие переподключения; WireGuard, ключи клиентов, второй выход и
   порядок fallback не меняются. Контейнеры VPN не перезапускаются.

Если контрольные пробы после подтверждённого применения не проходят, возвращается
прежняя конфигурация. Потерянное подтверждение применения не считается доказательством
отказа: задание остаётся `needs_reconcile`, автоматический повтор запрещён.
При потере ответа браузер опрашивает прежний ID, а не создаёт новую операцию.

Проверяется и закрепляется один публичный IP сервера с сохранением TLS SNI.
При смене IP у провайдера следует импортировать и проверить ссылку снова.
Не поддерживаются подписки, XHTTP/gRPC, произвольные YAML и отключение TLS-проверки.
Проверки HTTPS не доказывают качество UDP, игр, видеопотоков или всех сайтов.

## Секреты и эксплуатация

- URI не попадает в URL браузера, localStorage, задания, журнал или Git.
- Черновики — root-only каталог `private/profile-drafts` (0700), файлы 0600;
  срок использования 30 минут, максимум восемь, привязка к владельцу.
  Истёкшие записи удаляются при следующем чтении списка или импорте.
- Проверенный черновик привязан к ревизии конфигурации и правил. После чужого
  изменения его необходимо создать заново.
- В `private/profile-recovery` остаются root-only записи для разбора спорного
  результата. Они содержат прежнюю и новую конфигурацию; не публиковать их и
  не включать в незашифрованные диагностические выгрузки.
- Тестовый контейнер не публикует порт, не получает TUN/NET_ADMIN, работает
  с read-only rootfs и аутентификацией. Удаление проверяется по точному имени и
  метке. При неподтверждённой уборке исполнитель удерживает блокировку.
- После аварийного перезапуска исполнителя незавершённое задание требует
  проверки root-оператором; не удалять SQLite и не снимать блокировку вслепую.

Root-оператор включает адаптер файлом `private/profile-host.json` (0600):
`{"version":1,"image_id":"sha256:<64 hex>"}`. Дайджест должен совпадать с установленным
`vpn-mihomo` проекта `vpn-gateway`. Сам интерфейс не может выбирать образ или
команду. Отсутствие этого файла безопасно отключает импорт/замену.

Исполнитель использует тот же защищённый Unix-сокет и общую блокировку обслуживания.
Его обновление меняет идентификатор сборки Anti-DPI: готовность проверяется заново,
авторизация Auto не переносится. Общие обновления/рестарты компонентов этим
изменением не включаются.
